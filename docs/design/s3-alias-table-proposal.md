## 2. 登録済みテンプレートの節名から拾える対応

テンプレートがアーキタイプのルートに付けた名前（カードの `semantics.container_labels`）と、アーキタイプの組。
その名前は、そのテンプレートのカードではすでに検索に当たる（#31）。別名表に入れると、**同じアーキタイプを持つほかのテンプレートのカード**にも届く。

| テンプレートが付けた名前 | アーキタイプ | 出どころ | ほかの登録済みテンプレートに同じアーキタイプがあるか |
|---|---|---|---|
| 傷病名 | EVALUATION.problem_diagnosis.v1 | jp_referral | **ある**（ProblemList。そこでの名前は「プロブレム・診断」） |
| 既往歴及び家族歴 | OBSERVATION.story.v1 | jp_referral | 無い |
| 症状経過及び検査結果、治療経過 | EVALUATION.clinical_synopsis.v1 | jp_referral | 無い |
| 紹介元医療機関、紹介先医療機関、診療科 | CLUSTER.organisation.v1 | jp_referral | 無い |
| 医師、担当医 | CLUSTER.person.v1 | jp_referral | 無い |
| 検体検査結果 | OBSERVATION.laboratory_test_result.v1 | LabResultReport | 無い |
| 検査分析結果 | CLUSTER.laboratory_test_analyte.v1 | LabResultReport | 無い |

- いま効くのは 1 行だけ: **傷病名 → problem_diagnosis.v1**。jp_referral を登録していなくても、ProblemList のカードに「傷病名」で届くようになる
- 残りの行は、同じアーキタイプを持つテンプレートが増えたときに効く。**表に書かずに、登録のときに自動で集める**作りにもできる（3 節）
- 拾えたが案に入れていないもの: patient_blood_pressure.v1（ラベルが英語のまま）の「Blood Pressure」「Systolic」「Diastolic」と、
  CardiologyEncounter の「血圧」「収縮期」「拡張期」。アーキタイプの版が違い（blood_pressure.v1 と v2）、同じ at-code が同じ意味かは確かめていない

## 3. ゲートで問うこと

1. **1.1 節の 5 行を表に入れてよいか**（行ごとに可否）。「既往」は、対象が problem_diagnosis の全カードになる。どのカードを先に出すか（at0002 か）も決めてほしい
2. **1.2 節の「入れない」を、表に負の行として持つか**。持たなければ、文書に残すだけになる
3. **別名を引く単位**: 語の全体が一致したときだけ引く（「既往」は引き、「既往歴」は引かない）でよいか。部分一致で引くと、1.2 節の「既往歴」の件が起きる
4. **2 節の節名**: 人間がレビューする表に書くか、登録済みテンプレートから自動で集めるか。自動なら、テンプレートの作者が付けた名前が、レビューなしでほかのテンプレートの検索に効く
5. **表の置き場所と形**: 案は、リポジトリの中の YAML 1 つ（行 = 問いの語、対象のアーキタイプ ID と at-code、出どころ、`reviewed_by`、`reviewed_at`）。
   用語マスターの中身は入れない（コンテンツ防火壁）

## 4. 守ること

- LLM 分業原理: 別名表が供給するのは「問いの語 → カード」の対応付けだけ。カードの意味・パス・制約は OPT から取ったものを変えない
- 実物主義: 行の対象は、登録済みテンプレートに実在するアーキタイプ ID と at-code だけ。出どころを示せない語は入れない
- 評価: 表を入れる前後で、評価 v1・v2（と、足す問いの案 `docs/design/s3-eval-questions-proposal.md` のうち確定したもの）の before／after を取る
