## R8（2026-11-26）例外報告: 赤の PR をマージした。修正できるかの判定の時刻の欠陥（`skoba/anlage#171`）

- **何が起きたか**: PR #169（#168）を、head の CI が赤（run 45735999075）のまま、セッションがマージした → main `4ccabe2` が赤。
  - 原因はセッションの手順。「CI を待つ」と「マージ」を 1 つのコマンドに続けて書き、CI の結果を確かめなかった。
  - 以後、マージは、CI の結果を確かめたあとに別のコマンドで行う。
- **落ちた spec**: `spec/requests/record_versions_spec.rb:120`（`expected: "[lb_av]/[in_i]2"`、`got: nil`）。手元では通る。
- **原因**（ソースを読んだ。P4 の #138 からある欠陥）:
  - `Opt::CompositionEditability.editable?` は、読み戻して組み直した content を、原本とまるごと比べる。
  - 組み直しは、OBSERVATION の `EVENT.time` と `HISTORY.origin` に、組み直した時刻を入れる。
  - そのため、保存と判定が同じ秒でないと「修正できない」になる。利用者から見ると、OBSERVATION を含む記録は保存して 1 秒たつと修正できない。
- **判断（自己承認）**: 修正の版のイベント時刻は、元の記録の時刻を引き継ぐ。測った時刻は値を直しても変わらない。context/start_time（#146）と同じ考え方。
  - 判定と修正の保存は、どちらも元の時刻で組む（`Opt::RecordedTime.of`。最初の OBSERVATION の最初の EVENT の time を、原本の書き方のまま読む）。
  - 捨てた案: 比べるときに時刻の項目を外す。判定は通るが、修正の版の時刻が修正した時刻になる。
- **Red**: `record_versions_spec.rb` の #171 の例。1 時間あとに修正の帳票を開くと `expected … :ok (200) but it was :unprocessable_content (422)`。
