## R1 Docker での起動（2026-11-25）

### 実測

- main `20312e1` で `docker build -t anlage-v020-check .` は失敗した（exit 5）:
  ```
  An error occurred while installing fiddle (1.1.8), and Bundler cannot continue.
  openehr-rails was resolved to 0.9.0, which depends on
    openehr was resolved to 2.5.0, which depends on
      locale was resolved to 2.1.5, which depends on
        fiddle
  extconf failed, exit code 1
  ```
- 原因: ビルドの段（`FROM base AS build`）に libffi のヘッダが無い。`libffi-dev` を足すとビルドが通った（Docker 29.9.1）
- 起動: `docker run -e SECRET_KEY_BASE=… -p 3999:80` で、`/up`・`/templates`・`/patients` が 200（`config/master.key` 無し）。
  `bin/docker-entrypoint` が `db:prepare` を流すので、空の volume でも起動する
- README に書いた手順（`docker build` → `docker run … -v <volume>:/rails/storage` → `curl /up`）を、名前だけ変えてそのまま流し、200 を確認した。
  確認に使ったイメージと volume は消した

### 判断（自己承認、Issue #142 の範囲内）

- Dockerfile はビルドの段に `libffi-dev` を足すだけ（実行の段は `libvips` の依存で libffi が入るため、起動で落ちないことを実測で確認）
- TLS の設定（`assume_ssl`・`force_ssl`）は変えない。既知の制限に書いた（外に出すなら TLS を終端するプロキシの後ろ）
- `docker-compose.yml` は足さない（単一のコンテナで足りる。足すかは公開のあとの Issue に）
