# 例外報告: README.ja.md が空のまま main に入った（2026-11-27）

裁定 ID: R-20261127-27。起こしたのは、引く側のセッション（PR #240）。

## 何が起きたか

- anlage main で、`README.ja.md` が 0 バイトになっていた（`7344db1`。PR #240「docs/nl-query.md を英語版（主）に」。main `bb19ec1`、19:43 にマージ）
- 直前の版は `1949ff1` の 13,319 バイト・185 行。README.md は、その間も「English | [日本語](README.ja.md)」と案内していた
- 見つけたのは統括（20:50 ごろ）。1 時間ほど、main の日本語の README が空だった

## どの操作で空になったか

PR #240 で、README.ja.md の案内の 1 行（`docs/nl-query.md` → `docs/nl-query.ja.md`）を直すために、セッションが書いた 1 行のスクリプト:

```python
open('README.ja.md','w').write(open('README.ja.md').read().replace("…", "…"))
```

Python は、`open('README.ja.md','w')` を先に評価する。**書き込み用に開いた時点で、ファイルは空になる**。そのあとの `open('README.ja.md').read()` は、
空の文字を読み、空の文字を書き戻した。同じスクリプトの README.md の側は、先に `r = open('README.md').read()` で読んでから書いていたので、無事だった。

## なぜ、マージの前に気づかなかったか

1. スクリプトのあと、`git diff --stat` を見ずに `git add`・commit・push した。README.ja.md は「1 行の直し」と思い込んでいた
2. PR を開いたあとも、差分の削除の行数（README.ja.md −185）を見なかった。PR の本文には「README（日本語）のリンクを日本語版に向けた」と書いた（事実と違う）
3. PR #240 は、セッションがマージする前に、マージされていた（19:43。セッションの操作ではない）。ただし、セッションも、CI が green なら
   マージするつもりで待っていた。**マージの前に差分を見る手順が、セッションに無かった**ので、だれがマージしても同じ結果になっていた
4. CI は、README の中身を見ていなかった

## 直したこと

1. `README.ja.md` を、`1949ff1` の版から、git で取り出して戻した（`git show 1949ff1:README.ja.md`。取り出した直後に、`cmp` で同じであることを確かめた）
2. その上で、意図していた 1 行（nl-query の案内を、日本語版の文書に向ける）を入れた
3. 戻した版と `1949ff1` の版の差分は、その 1 行だけ（PR の本文に載せた）

## 再発を防ぐ

- spec（regression pin）: `spec/docs/readme_spec.rb`。README.md と README.ja.md が空でなく、先頭で互いに案内している。追跡している `.md` に 0 バイトのものが無い。
  空の README.ja.md に対して 3 例とも落ちることを確かめてから、戻した
- セッションの手順:
  - commit の前に `git diff --stat` を見る。**マージの前に、PR の差分の「消えた行」を見る**。docs の PR で、意図しない大きな削除があれば、マージしない
  - ファイルの書き換えは、読んでから書く（読むのと書くのを、1 つの式に入れない）。書く前に、読んだ中身の大きさを確かめる
