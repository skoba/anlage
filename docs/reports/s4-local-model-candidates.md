# ゲート報告: 手元で動かすモデルの候補（S4 の段 5）

裁定 ID: R-20261127-14（Q3「手元のモデルは、候補を出したところでゲート報告」、段 5）。計画書: `docs/design/s4-nl-aql-plan.md` 3.3 節・7 節。

**何も入れていない。何も動かしていない。** 道具とモデルを入れるのは開発機の設定の変更なので、承認を待つ。
この報告の候補は、Web の検索で拾った手がかりで、**どれも、この開発機で動かして確かめたものではない**。

## 開発機（実測。2026-11-27）

| | |
|---|---|
| CPU | 8 コア（WSL2） |
| メモリ | 15 GB（空きは 7 GB ほど） |
| GPU | 見えない（`nvidia-smi` が無い） |
| 手元のモデルを動かす道具 | 入っていない（`ollama`、`llama-server` とも無い）。Docker は動いている |
| 空きの容量 | 923 GB |

- GPU が無く、空きのメモリが 7 GB ほどなので、動かせるのは、小さいモデル（4 ビットに量子化した、4B〜8B の大きさ）まで、という見込み
- CPU だけなので、遅い見込み。指示文とカードの文で入力が数千トークンあり、1 問に数十秒〜数分かかるかもしれない（未確認）

## 問うこと

| # | 問い | 推す案 |
|---|---|---|
| L1 | 道具に何を使うか | **Ollama を、Docker のコンテナで動かす**（ホストには入れない。像と、モデルのファイルを置く volume だけが増える） |
| L2 | 入れてよいか（開発機の設定の変更） | コンテナ 1 つと、モデルのファイル（1 つ数 GB）を 2〜3 個。使い終わったら消せる |
| L3 | どのモデルを試すか | 下の候補から 2〜3 個を、日本語の問いと JSON の出力で試し、1 つに絞る |
| L4 | 遅すぎたとき | 測定の回数を減らす（5 回 → 固定した 1 回と、固定しない 2 回など）か、手元のモデルを測定から外す。試した結果を見て、もう一度報告する |

## 道具の候補

| 道具 | 長所 | 短所 |
|---|---|---|
| **Ollama（推す）** | HTTP の口があり、Ruby の標準の `Net::HTTP` で呼べる（gem を足さない。計画書 6.1 節）。JSON の形を渡して、出力を縛れる（`format` に JSON スキーマ）。Docker の像がある | 口の細かい点（`format` の扱い、乱数の種）は、公式の文書を読んで確かめる必要がある（まだ読んでいない） |
| llama.cpp の `llama-server` | 依存が少ない。量子化したファイルを直接使う | モデルのファイルを自分で選んで取ってくる手間がある |

- Ollama は、OpenAI と互換の口（`/v1/chat/completions`）も持つ。アダプタを「OpenAI と互換の口」向けに書けば、ほかの道具（llama.cpp、LM Studio など）にも使える。
  ただし、互換の口は、元の口の機能の一部だけ、との記述がある。どちらの口に書くかは、公式の文書を読んでから決める

## モデルの候補（手がかり。未確認）

| 候補 | 大きさの見込み | 手がかり |
|---|---|---|
| Qwen 系の小さいもの（4B〜8B。4 ビットの量子化） | 3〜6 GB | 複数の案内が、日本語では Qwen 系が強い、と書く。JSON の形を縛る例にも使われている |
| 日本語に寄せた小さいモデル（LFM2.5 1.2B JP など） | 1 GB ほど | 検索に出てきた。中身は読んでいない。小さいので速いが、選択の JSON を作れるかは分からない |
| Qwen 系の 14B（4 ビット） | 9 GB ほど | 案内では 16 GB の機械の上限、とされる。**この開発機の空き（7 GB）では、たぶん動かない**。候補から外す |

- モデルの正確な名前、大きさ、ライセンスは、入れる前に、配布元のページで確かめる（ここには書いていない）
- 手元のモデルは、外に何も送らない。扱うのはサンプルデータだけ、という条件は、API のモデルと同じ

## 試し方（承認のあと）

1. コンテナを立て、候補を 1 つずつ入れる
2. 調整用の問い（PR #233 の t001〜t003。測定には使わない）で、選択の JSON が返るか、1 問に何秒かかるかを見る
3. 1 つに絞り、`Llm::Adapters::Local` を書く（偽の HTTP の口の spec から。外も、手元のモデルも、CI からは呼ばない）
4. 結果（どれを選んだか、速さ、JSON として読めた率）を、ログに書く
