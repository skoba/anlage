## 道具の候補

| 道具 | 長所 | 短所 |
|---|---|---|
| **Ollama（推す）** | HTTP の口があり、Ruby の標準の `Net::HTTP` で呼べる（gem を足さない。計画書 6.1 節）。JSON の形を渡して、出力を縛れる（`format` に JSON スキーマ）。Docker の像がある | 口の細かい点（`format` の扱い、乱数の種）は、公式の文書を読んで確かめる必要がある（まだ読んでいない） |

- Ollama は、OpenAI と互換の口（`/v1/chat/completions`）も持つ。アダプタを「OpenAI と互換の口」向けに書けば、ほかの道具（llama.cpp、LM Studio など）にも使える。
  ただし、互換の口は、元の口の機能の一部だけ、との記述がある。どちらの口に書くかは、公式の文書を読んでから決める

### M1 を試した結果（同じ日。同じコンテナ、同じモデル。調整用の 3 問）

公式の文書（docs.ollama.com の capabilities/thinking、api/chat）で確かめたこと: 元の口 `POST /api/chat` は、`think: false`（考える分を出さない）、
`format`（`json` か JSON スキーマ）、`options`（`temperature`、`num_predict`、`num_ctx`、`seed`）を受ける。応答は `message.content`、
`prompt_eval_count`・`eval_count`、時間は ns。OpenAI と同じ形の口では、`reasoning_effort` の `"none"` が、考える分を止める指定にあたる。
`/no_think` は、Ollama の文書には無い。

| 指定（元の口 `/api/chat`） | t001 | t002 | t003 | 読めたか |
|---|---|---|---|---|
| `think: false`、`num_predict: 400` | 222 秒（入力を読む 73 秒＋生成 115 秒） | 163 秒 | 162 秒 | **0/3**。モデルが、本文に英語で考えを書き始め、400 トークンで切れた |
| 上に、`format`（選択の形の JSON スキーマ）を足す | 22 秒 | 30 秒 | 17 秒 | **3/3**。出力は 68〜80 トークン |

- **2 行めの時間は、入力を読む時間が入っていない**（0.4〜0.5 秒）。直前に同じ文を送っていて、道具が、読んだ結果を使い回したため。
  はじめて送る文では、1 行めの「入力を読む 50〜73 秒」が足される見込みで、**1 問 70〜100 秒ほど**（見込み。はじめて送る文で、形を縛って測ってはいない）
- 選んだ中身（期待行は無いので、読んで見ただけ）:
  - t001「拡張期血圧が 90 以上の記録の、拡張期血圧の値」: 条件は拡張期 `>= 90` で合っているが、**表示する項目に収縮期を選んだ**（誤り）
  - t002「診断確度が『推定』の傷病の、傷病名」: 傷病名（紹介状のカード）と、診断確度 = 推定。組まれる AQL は、期待する形と同じになる
  - t003「体重が 60 kg 以上の記録の、体重の値」: 体重 `>= 60`。合っている
- 出力の形を縛ると、このモデルでも、選択の JSON が返る。**縛らないと、読めない**。Claude API と OpenAI のアダプタで、出力の形を縛る機能を
  まだ使っていない件（計画書 2.2 節、ログ R4 の A5）にも、かかわる材料

### 見込みの直し

1 問 70〜100 秒とすると、選択を出す腕だけで、31 問 × 5 回 = 155 回が **3〜4 時間**ほど。10 時間（上の見込み）よりは短いが、開発機の CPU を 4 コア使い続ける。

| # | 問い | 推す案 |
|---|---|---|
| M1' | アダプタの形 | **Ollama の元の口（`/api/chat`）に、別のアダプタ（`local`）を書く**。`think: false` と `format` を使う。OpenAI と同じ形の口のアダプタ（`openai` の接続先を変える）でも呼べるが、そちらでは、考える分が止まらず、1 問 4 分かかった（実測）。出力の形（選択の JSON スキーマ）を、アダプタに渡す引数を足すことになる（`complete(instructions:, input:, json_schema: nil)`。汎用の口のまま） |

| M3 | 手元のモデルの測定の大きさ | 選択を出す腕だけ、5 回（3〜4 時間）。接地なしの腕と AQL を書かせる腕は、手元のモデルでは測らない |

## 回答（R-20261127-29）と、アダプタを書いたあとの実測（2026-11-27）

回答: M1' は推す案のとおり（Ollama の元の口に、別のアダプタ `local`）。M2 は qwen3:4b に絞る。M3 は、選択を出す腕だけ・5 回。M4 は、測定から外さず、
成績を API のモデルと別の区分で出す。M5（GPU のある機械）は、いまは採らない。

`Llm::Adapters::Local` を書いた（`skoba/anlage#245`。計画書 14 節）。アプリのアダプタ経由で、調整用の 3 問を、初期データの 18 枚で測った。

| 問い | かかった時間 | 結果 |
|---|---|---|
| t003 | 138 秒（コンテナを立てた直後。モデルの読み込みを含む） | 選択ができた |
| t002 | 31 秒 | はねた（値集合の項目に `=`） |
| t001 | 33 秒 | 選択ができた |

- モデルを読み込んだあとは、1 問 30 秒ほど。上の見込み（70〜100 秒）より短い。上の試しは 44 枚（入力 2,470 トークン）、こちらは 18 枚（1,400 トークンほど）
- 見込みの直し: 37 文 × 5 回 = 185 回で、1 時間半〜2 時間ほど（3 問の数字からの見込み）。6 時間を超えないので、回す前の報告は要らない見込み
- コンテナは止めてある。像と、モデルのファイルは残っている。測定が済んだら消す
